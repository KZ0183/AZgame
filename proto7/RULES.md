# ふたりの英雄（仮）対応版 ルール v0.2

`proto6`（同時計画制）から、MTG のような**攻守交代＋対応**の形に作り替えた試作。比較のため `proto6` はそのまま残している。
ブラウザで `index.html` を開けば CPU と対戦できる。

## ねらい

- 同時処理だと「計画をまとめて出して結果を見る」だけで、1枚ずつ考える手応えが薄かった
- 相手の攻撃に1枚ずつ「対応」できるようにして、「この攻撃にこのカードで返す」駆け引きを作る

## 構成

| ファイル | 内容 |
| --- | --- |
| `engine.js` | ルールエンジンと CPU。DOM に依存しない（Node でも動く） |
| `index.html` | 画面（タイトル・ヒーロー選択・対戦） |

## 基本

- ヒーローを**2人**選ぶだけでデッキが決まる。各ヒーローは固有のカードを**3枚**持つ
- ヒーローは**前衛**か**後衛**に立つ。前衛向けの攻撃は後衛に届かない（遠距離技は届く）
- お互いの陣地に**タワー**（HP20）。**相手のタワーを壊したら勝ち**
  - いつでも狙えるが、持ち主の前衛に誰かいるあいだは、殴ったヒーローに**4ダメージの反撃**
  - 前衛が空なら無防備で、反撃はない
- 10ラウンドで決まらなければ、タワーの残りHP → ヒーローの残りHPで判定

## ターン

- 先攻・後攻はランダム。1ラウンド＝お互いが1ターンずつ
- **自分のターンの始め**に
  - マナが回復する：**ラウンド数+1**（上限6）。先攻の最初のターンだけ1
  - 倒れていたヒーローは、**自分のターンを1回休んでから**、次の自分のターンの始めに後衛で全快復活する（v0.2）
  - 自分のヒーローの盾・挑発が切れる
  - 各ヒーローが、今いる位置に合ったカードを生む。**前衛は2枚、後衛は1枚**（v0.2。手札は最大5枚）
- 自分のターンには、次を**1つずつ**行う（マナが続く限り何回でも）
  - カードを使う（前衛用のカードは、そのヒーローが前衛にいるときだけ）
  - 前衛のヒーローで**通常攻撃**（1マナ・1人1ターン1回・攻撃力ぶんのダメージ）
  - **移動**（1マナ・1人1ターン1回）：前衛と後衛を入れ替える
- カードも通常攻撃も、**選ぶ →（対象を選ぶ）→「使う」で確定**の1枚ずつの流れ。確定するまでは何も起きず、対象の選び直しや取りやめができる
- 「ターン終了」を押すか、時間切れでターンが終わる（1ターンの時間は30秒・60秒・なしから選べる）

## 対応

- 相手が**攻撃**（通常攻撃か攻撃カード）を宣言すると、こちらは**対応カード**を1枚使える
- 対応が先に処理され、そのあと攻撃が処理される
- **対応への対応はない**（1段だけ）
- 移動や支援カードには対応できない
- **使わずに残したマナ**は、相手のターンの対応に使える。マナは次の自分のターンの始めに回復し直す
- 受付時間は**5秒**。対応できるカードがなくても、同じだけ待つ（待ち時間から手札が読まれないように）。「対応しない」で即スキップできる
- CPU が対応するかを考えるときも、約1秒待つ

### 対応カード（5枚）

| カード | ヒーロー | 位置 | 対応で使ったときの効果 |
| --- | --- | --- | --- |
| 加護【1】 | 聖女 | 後 | 味方1人に盾3。狙われた味方が初期の対象 |
| 癒しの光【1】 | 聖女 | 後 | 味方1人のHPを3回復 |
| 守りの構え【1】 | 守護騎士 | 後 | 味方1人に盾4 |
| 挑発【1】 | 守護騎士 | 前 | その攻撃（と次の自分のターンまでの攻撃）を守護騎士に引きつける |
| 足払い【1】 | 盗賊 | 前 | 攻撃してきた前衛に1ダメージを与えて後衛に下げる。前衛からの攻撃は不発になる |

対応カードは、自分のターンに普通に使うこともできる。盾と挑発は、次の自分のターンの始めまで続く。

## 同時計画制（proto6）からなくなったもの

- 素早さと、同時処理の順番のルール（行動は1つずつ順に処理される）
- 計画の予約と取り消し
- 「移動で空振りさせる」読み合い（「対応の足払いで不発にする」に置き換わった）

## CPU

- 自分のターン：できる行動を全部試し、評価が良くなる限り1つずつ行う。対応カードを持っていれば、そのコストぶんのマナを残すことにも価値を置く
- 対応：対応しない場合と、各対応を使った場合を比べ、少しでも得なら使う
- 相手の手札は見ない（ただし後衛の正体は見えている。試作のための手抜き）

## 画面

- 攻撃の向きを**矢印**で表示する。相手の攻撃は赤（対応を考えているあいだは点線が流れる）、自分の攻撃は金色、味方への支援は緑
- 倒れたヒーローには「あと何ターンで復活」を表示する

## CPU 同士のシミュレーション（v0.2、250試合）

v0.1 の課題（攻め手が足りず、前衛を倒してもタワーを殴りきれない）への調整を比べた。

| 調整 | 上限まで行く試合 | 先攻の勝率 |
| --- | --- | --- |
| v0.1 のまま | 約41% | 約48% |
| 倒されたら自分のターンを1回休む | 約38% | 約48% |
| ＋前衛は2枚生む（**採用**） | 約28〜29% | 約48〜49% |
| ＋前衛は2枚生む＋通常攻撃0マナ | 約25% | 約51% |
| 前衛は2枚生む＋自分のターンを2回休む | 約31% | 約51% |

- 1試合あたり、対応は約2.5回
- ヒーロー別の勝率：剣士 約74%、盗賊 約70%、守護騎士 約45%、聖女 約38%、魔術師 約25%

## CPU 同士のシミュレーション（v0.1、300試合）

- 先攻の勝率は約53%
- 1試合あたりの攻撃は約32回、対応は約3.3回。5種類の対応カードはどれも使われる（多い順に挑発・加護・癒しの光・守りの構え・足払い）
- **10ラウンドの上限まで行く試合が約40%と多い**
- ヒーロー別の勝率：盗賊 約70%、剣士 約68%、守護騎士 約49%、聖女 約39%、魔術師 約25%

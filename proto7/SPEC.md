# ふたりの英雄（仮）仕様まとめ

対応版 v0.6 時点の仕様。変更の経緯とシミュレーションの記録は `RULES.md` にある。

## 1. 概要

- 2人対戦のカードゲーム。スマホ縦画面、1試合5〜7分ほど
- デッキ構築は**ヒーローを2人選ぶだけ**
- 攻守交代のターン制で、相手の攻撃には**対応**（割り込み）ができる
- 相手の**ライフを0にしたら勝ち**

> ライフは、画面とエンジンでは「タワー」と呼んでいる。ブロックが入ってからは、役割は他のカードゲームのプレイヤー本人のライフと同じになった。

## 2. 準備

- 5人のヒーローから**2人**を選び、どちらが最初に前衛に立つかを決める
- ライフは各**20**
- 先攻・後攻はランダム
- 各ヒーローの4枚のカードを、ヒーローごとに**シャッフルして巡回の順番**を決める。上の2枚が手札になる

## 3. 盤面と陣形

- 各プレイヤーの陣地には、**前衛**と**後衛**の2つの列がある。ヒーローはどちらかに立つ
- **前衛**：前衛用のカードと固有スキルが使える。前衛向けの攻撃を受ける。プレイヤーへの攻撃を**ブロック**できる
- **後衛**：前衛向けの攻撃を受けない（遠距離の攻撃は受ける）
- 前衛が誰もいないと、プレイヤーは**無防備**になる（ブロックできない）
- 相手の後衛のヒーローは、前衛に出るか、行動するか、ダメージを受けるまで正体が見えない

## 4. ターンの流れ

1ラウンド＝お互いが1ターンずつ。最大10ラウンド。

### ターンの始め
- マナが回復する：**ラウンド数+1**（上限6）。最初のラウンドだけ、先攻は1、後攻は3
- 休んでいた（倒された）ヒーローが復活する（→ 7）
- 自分のヒーローの盾・挑発・かばう・ブロックの使用・スキルと移動の使用がリセットされる

### 自分のターンにできること
次を**1つずつ**、マナが続く限り何回でも行う。どれも「選ぶ →（対象を選ぶ）→ 使う」で確定する。

| 行動 | マナ | 回数 |
| --- | --- | --- |
| カードを使う | カードごと | 手札がある限り |
| 固有スキルを使う | 1 | 1人1ターン1回 |
| 移動（前衛⇔後衛） | 0 | 1人1ターン1回 |

「ターン終了」を押すか、時間切れで相手のターンになる。
**使わずに残したマナは、相手のターンの対応に使える。**

## 5. カードの巡回

- 各ヒーローは固有の**4枚**のカードを持つ。手札は**ヒーローごとに2枚**
- カードを使うと、そのカードは列の最後へ回り、列の先頭のカードが**使ったカードと同じ場所に**入る
- 巡回の順番は相手に見えない。使ったカードは公開されるので、**覚えていれば相手の手札が読める**（履歴は表示しない）
- 「前衛」の付いたカードは、そのヒーローが前衛にいるときだけ使える
- 倒されても巡回は続く。手札も失わない

## 6. 攻撃・対応・ブロック

### 攻撃
- 攻撃カードと攻撃系の固有スキルが「攻撃」。狙えるのは相手のヒーローかプレイヤー
- **前衛向け**の攻撃は、相手の前衛のヒーローかプレイヤーに届く。後衛に向けると空振り
- **遠距離**の攻撃は、後衛のヒーローにも届く

### 対応
- 相手が**攻撃**を宣言すると、こちらは**1つだけ割り込める**。割り込みが先に処理され、そのあと攻撃が処理される
- 割り込めるもの
  - 「対応」の付いたカード（マナが要る）
  - 守護騎士の固有スキル「かばう」（1マナ）
  - **ブロック**（プレイヤーへの攻撃のとき、マナ不要）
- 対応への対応はない
- 受付は**5秒**。割り込めるものがなくても同じだけ待つ（待ち時間から手札を読まれないように）

### ブロック
- プレイヤーへの攻撃を、**前衛のヒーローが代わりに受ける**
- マナ不要。**前衛1人につき、相手のターンに1回**まで
- ブロックしたヒーローは反撃しない（ヒーローのHPでライフを買う取引）

## 7. ダメージ・撃破

- 盾があれば、先に盾が減る
- ヒーローのHPが0になると**倒れる**
  - そのヒーローの持ち主は、**ライフに4ダメージ**
  - 倒れたヒーローは、持ち主の**自分のターンを1回休んでから**、後衛で全快して復活する
- ライフが0になったら負け
- 10ラウンドで決まらなければ、残りライフ → ヒーローの残りHPの合計で判定

## 10. 画面

- **タイトル**：要点3つ、設定（1ターンの時間：30秒・60秒・なし／処理の再生：自動・「次へ」）、対戦・ヒーロー選択・ルール
- **対戦**（上から）
  - 相手のバー（相手のマナ）
  - 相手のライフ（タワー）→ 相手の後衛・前衛
  - **真ん中の帯**：ラウンド、どちらのターンか、今のフェーズと残り時間
  - 自分の前衛・後衛 → 自分のライフ（タワー）
  - 自分のバー（マナ）
  - 手札（ヒーローごとに2枚と、次に来るカード）
  - 説明欄（選んだもの、ヒーローの詳細、処理の再生中は段階の題と「なぜ」）
  - ボタン
- 攻撃の向きは**矢印**で表示する（相手の攻撃は赤、自分は金、味方への支援は緑）
- 手番の側の盤面はうっすら色付けし、ターンが替わった瞬間に大きく表示する
- 処理は段階ごとに再生し、空振り・ブロック・かばうなどの理由を「なぜ」として表示する

## 11. CPU

- 自分のターン：できる行動を全部試し、評価が良くなる限り1つずつ行う。対応カードを持っていれば、マナを残すことにも価値を置く
- 対応：何もしない場合と、各対応・ブロックを使った場合を比べて選ぶ
- 相手の手札は見ない（後衛の正体は見えている。試作のための手抜き）

## 12. 現在のバランス（CPU 同士、300試合）

- 平均6.2ラウンドで決着。10ラウンドまで行く試合は約9%
- 先攻の勝率 約54%
- ヒーロー別の勝率：剣士 約73%、聖女 約57%、盗賊 約56%、守護騎士 約33%、魔術師 約30%

## 13. 残っている課題

- ヒーローの強さの差（剣士が強く、守護騎士と魔術師が弱い）
- 「タワー」の名前と見た目を、プレイヤーのライフとして見せるか
- CPU は守護騎士の「かばう」を自分のターンに使わない（守る価値を先読みできない）
- オンライン対戦（送るのは行動と対応だけ、処理はエンジンが決定的に行う想定）
- 試合をまたぐやり込み要素（カードの見た目など、強さに関わらないもの）

# ふたりの英雄（仮）ルール v0.4

2人のヒーローを前衛・後衛に立たせて戦う、2人対戦のカードゲーム。スマホ縦画面を想定。
`proto5`（五枚決闘）の議論から方向を変えた試作。ブラウザで `index.html` を開けば CPU と対戦できる。

v0.3 で、交互のターンをやめて**同時計画制**にした。v0.4 で、勝利条件をノックアウトから**タワーの破壊**に変えた。お互いが同じ時間で行動を予約し、確定したら同時に処理する。
将来のオンライン対戦では、送るのは「計画」だけで、処理は `resolveRound` が決定的に行う想定。

## 考え方

- デッキ構築は**ヒーローを2人選ぶだけ**。カードはヒーローが生み出す
- 各ヒーローは固有のカードを**5枚**持つ（Lv1で3枚、Lv2で1枚、Lv3で覚醒カード1枚が解放される）
- 育成は**対戦中だけ**。試合をまたぐ育成は、見た目などの強さに関わらないやり込み要素にする（未実装）
- レベルアップは**マナで買う**。コストはヒーローごとに違い、それが育ち方の個性になる
- 勝敗は**タワーの破壊**。ヒーローを倒しても点にはならず、「タワーを殴る隙を作る」意味を持つ
- 処理の時間が見どころになるよう、行動を1段階ずつアニメーション付きで見せる

## 陣形

- ヒーローは**前衛**か**後衛**に立つ。最初にどちらを前衛にするかは選べる
- **前衛**：通常攻撃と前衛用のカードが使える。前衛向けの攻撃を受ける
- **後衛**：通常攻撃はできない。タワーに守られていて、前衛向けの攻撃は届かない（遠距離の技だけ届く）

## ラウンドの流れ

1. **ラウンド開始**
   - お互いのマナ＝**ラウンド数+2**（上限6）。余っても持ち越さない
   - 倒れていたヒーローが**後衛で全快復活**する（Lv1に戻る）
   - 盾・挑発・不屈・気合いが切れる
   - 各ヒーローが、**今いる位置に合ったカードを1枚生む**（前衛なら前衛用、後衛なら後衛用。解放済みのものからランダム）。手札は最大5枚で、溢れた分は消える
2. **計画（30秒）**：お互いが同時に行動を予約する。CPU戦でもタイマーは動く
   - 予約できる行動（マナが続く限り何個でも）
     - **移動**（1マナ・1人1ラウンド1回）：前衛と後衛を入れ替える
     - **レベルアップ**（ヒーローごとのコスト）
     - **カード**。前衛用のカードは、移動の予約を反映した位置で前衛にいれば使える
     - **通常攻撃**（1マナ・前衛のみ・1人1ラウンド1回・攻撃力ぶんのダメージ）
   - 予約はいつでも取り消せる。取り消すと、成り立たなくなった後ろの予約も外れる
   - 祈り・瞑想のマナは、予約した時点で使えるようになる
   - 「確定する」を押すか、**時間切れ**で確定する（時間切れのときは、それまでの予約で確定）
3. **同時に処理**（次の順）
   1. **移動**
   2. **レベルアップ**。得たカードは手札に入るが、使えるのは次のラウンドから
   3. **守り・支援**（盾・回復・挑発・盗みなど）
   4. **攻撃**：**素早い順**。同じ素早さのヒーローの行動はまとめて処理し、倒れる判定はまとまりの最後に行う
   - 同じ段階・同じ素早さでの先後は、ラウンドごとに交代する（奇数ラウンドはあなたが先）

## 攻撃の当たり方

- 攻撃は「ヒーロー」を狙う
- **空振り**：前衛向けの攻撃は、狙った相手がそのときに後衛にいれば空振りする。狙った相手が先に倒れていても空振り。払ったマナは戻らない
- 遠距離の攻撃は、相手が後衛にいても当たる
- **挑発**：守り・支援の段階で張られるので、そのラウンドの攻撃はすべて挑発したヒーローに向く
- 攻撃するヒーローが先に倒されていたら、その行動は不発
- 盾があれば、先に盾がダメージを受ける

## タワーと勝敗

- お互いの陣地に**タワー**（HP20）がある。**相手のタワーを壊したら勝ち**
- タワーは、前衛向けの攻撃でも遠距離攻撃でも、**いつでも狙える**
- **守られているタワー**（持ち主の前衛に誰かいる）を殴ると、殴ったヒーローに**4ダメージの反撃**が来る。攻撃1回ごと（連撃なら2回）。反撃で倒れることもある
- **無防備なタワー**（持ち主の前衛が空）は、反撃なしで殴れる
- 守られているかどうかは、その攻撃を処理する時点で判定する（移動や撃破のあと）
- 範囲攻撃（火炎・隕石・影分身）は、タワーには当たらない
- 挑発があると、タワーを狙った攻撃も挑発したヒーローに向く
- 倒されたヒーローは、次のラウンドにLv1・全快で後衛に復活する。そのヒーローのカードは手札から消える
- 両方のタワーが同じまとまりで壊れたら、残りHP（マイナスの小さい方）で判定
- 10ラウンドで決まらなければ、タワーの残りHP → ヒーローの残りHPの合計で判定

## 非公開の要素

- 相手の後衛ヒーローは、前衛に出るか、行動するか、ダメージを受けるまで「？？？」と表示される
- 相手の手札は枚数だけ見える
- 計画の中身は、処理の始めに「計画を公開」で両者に見える

## CPU

- 相手の手札や計画は見ない。相手の計画は「前衛が通常攻撃してくる」と見積もる
- 予約できる行動を全部試し、そのラウンドを処理した結果の評価が良くなる限り、計画に行動を足していく
- 評価：点数、HP・レベル、次のラウンドに倒されそうな前衛の危険度、手札が溢れそうかどうか
- 用意した二人組は5組から、ランダムに選ぶ

## CPU 同士のシミュレーション（v0.4、300試合）

- 決着は3〜4ラウンド目（約33%）と、10ラウンドの上限（約23%）に二極化している
- 前衛が空になる（タワーが無防備になる）ことは少ない（約7%）。「誰かが前に出ないといけない」は機能している
- CPU は反撃を受けても、守られたタワーを1試合に約8回殴る。CPU の評価が「タワー1ダメージ」を「ヒーロー1ダメージ」の3倍に見ているためで、人が遊んだときの感触とは違う可能性が高い
- 試した調整（エンジンの設定値として残してある。今は無効）
  - 反撃を6〜8に上げる：守られたタワーへの攻撃はほとんど減らない
  - 守られたタワーへのダメージを半分にする（`TOWER_GUARD`）：約8割が上限まで行く。逆効果
  - 倒されたヒーローが1ラウンド休んでから復活する（`REVIVE_WAIT`）：上限まで行く試合が増える
- **ヒーロー別の勝率に差が大きい**：剣士 約71%、盗賊 約69%、守護騎士 約43%、聖女 約41%、魔術師 約27%

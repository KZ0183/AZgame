# スマホ実機で確認する

開発中のビルドを手元のスマホで触るための手順。3 つの経路があり、
**まずは経路 A（Web）を推奨する**。iPhone でも Android でも使え、
インストール作業がいらないため、確認サイクルが最も速い。

| 経路 | 対応端末 | 準備 | 反映まで | 向いている確認 |
| --- | --- | --- | --- | --- |
| A. Web を開く | iPhone / Android | 初回のみ | 数分（自動） | レイアウト、ルール、手触り |
| B. APK を入れる | Android のみ | 初回のみ | 数分（自動） | 実機の描画性能、タップの追従 |
| C. 手元の PC から流す | iPhone / Android | Flutter 環境 | 即時 | 作りながらの試行錯誤 |
| D. 同じ Wi-Fi で配信 | iPhone / Android | Flutter 環境 | 即時 | A が使えないときの代替 |

このリポジトリは public なので、経路 A がそのまま使える。

> **private に戻す場合の注意。** GitHub Pages は private リポジトリでは
> GitHub Pro 以上のプランでないと使えない。無料プランで private に戻すと
> 経路 A が使えなくなるため、そのときは経路 B / D に切り替える。

---

## A. Web を開く（推奨）

ブランチに push すると GitHub Actions が Web ビルドを作り、GitHub Pages に
公開する。スマホのブラウザで URL を開くだけで最新版に触れる。

### 初回だけ必要な設定

1. リポジトリの **Settings → Pages** を開く
2. **Source** を **GitHub Actions** に変更して保存

これだけ。以降は push するたびに自動で更新される。

> `main` 以外のブランチからの公開が拒否される場合は、
> **Settings → Environments → github-pages → Deployment branches** に
> 対象ブランチを追加する。

### 使い方

スマホのブラウザで次の URL を開く。

**https://kz0183.github.io/AZgame/**

URL は固定なので、一度ブックマークに入れてしまえば以降は開くだけでよい。
push するたびに中身が最新版へ差し替わる。

最新の公開がいつ終わったかは、**Actions → 「スマホ確認用 Web を公開」**
の実行状況で確認できる。

### ホーム画面に追加すると実機アプリに近づく

ブラウザのアドレスバーが消えて全画面で起動し、縦向きに固定される。
盤面の見え方を確認するならこちらのほうが正確。

- **iPhone (Safari)**: 共有ボタン → 「ホーム画面に追加」
- **Android (Chrome)**: メニュー → 「ホーム画面に追加」

### この経路の限界

Web 版は実機アプリそのものではない。以下は経路 B / C で確認する。

- 描画性能（Web は CanvasKit 経由なので、実機アプリより重い）
- 端末の戻るジェスチャーやバックボタンの挙動
- 端末フォントの見え方

## B. Android 実機に APK を入れる

push のたびに Release の添付ファイルとして APK が更新される。

1. **Android のブラウザで** リポジトリの
   **Releases → 「開発ビルド（最新）」** を開く
2. `azgame-<コミット>.apk` をタップしてダウンロード
3. 通知またはダウンロード一覧からタップしてインストール
4. 「提供元不明のアプリ」の許可を求められたら、ブラウザに対して許可する

> **Actions の Artifacts からは落とさないこと。**
> Artifacts は必ず zip で固められて配布されるため、スマホでは展開の手間がかかる。
> Release の添付は `.apk` のまま配信されるので、タップするだけでインストールできる。

### 注意

デバッグ鍵で署名しているため、この APK はストア配信には使えない。
また、署名が変わると上書きインストールできないことがある。
その場合は一度アンインストールしてから入れ直す。

## C. 手元の PC から流す（作りながら確認する場合）

コードを書き換えた瞬間に実機へ反映されるので、UI を詰める作業はこれが最速。

```sh
flutter devices        # 接続中の端末を確認
flutter run            # 実機に流し込む
```

実行中に `r` でホットリロード、`R` でホットリスタート。

- **Android**: USB デバッグを有効にして USB 接続するだけ
- **iPhone**: Xcode と Apple ID が必要。無料の Apple ID でも実機に入れられるが、
  7 日でアプリの署名が切れるため入れ直しが必要になる

### iPhone に配布する場合

TestFlight や Ad Hoc 配布には **Apple Developer Program（有料）** の登録が要る。
登録前の段階では、iPhone での確認は経路 A（Web）が現実的。

## D. 同じ Wi-Fi 上の PC から配信する

経路 A が使えない場合（private リポジトリで Pages が有効にできないなど）の代替。
PC で Web 版を立ち上げ、スマホから PC の IP を直接開く。
GitHub のプランに左右されず、iPhone でも使える。

```sh
# PC の LAN 内 IP を調べる（例: 192.168.1.23）
#   macOS : ipconfig getifaddr en0
#   Linux : hostname -I
#   Windows : ipconfig

flutter run -d web-server --web-hostname 0.0.0.0 --web-port 8080
```

スマホのブラウザで `http://192.168.1.23:8080` を開く。
PC とスマホが同じ Wi-Fi につながっている必要がある。

> PC のファイアウォールが 8080 番を塞いでいると開けない。
> 接続できない場合はまず PC 自身のブラウザで `http://localhost:8080` を確認し、
> そこが映るならファイアウォールを疑う。

## どの経路で何を見るか

- **ルールが面白いか、盤面が読めるか** → A（Web）。反復が速いので、
  ここでの気づきが設計に一番効く
- **カードのタップが気持ちよく反応するか** → B か C
- **文字の見え方、フォント** → B か C。Web 版はブラウザのフォントで描かれるため、
  実機アプリとは見た目が変わる

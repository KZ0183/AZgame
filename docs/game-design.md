# AZgame ゲームデザイン仕様書 v0.3

> スマートフォン向け デッキ構築型カードゲーム
> A〜Z の文字を戦場に並べ、単語の陣形を組んで戦う。

---

## 1. コンセプト

### 1.1 一行で言うと

**文字たちが戦場に並んで戦い、単語として揃うと真価を発揮するカードバトル。**

### 1.2 v0.2 からの転換

v0.2 は「単語を作るために文字を並べる」ゲームだった。文字は単語の材料でしかなく、
盤面に置かれた `Z` が `Z` である必然性は、単語に必要かどうかだけだった。
単語が成立すると文字は消え、また一から並べ直す。文字に人格がなかった。

v0.3 では Magic: The Gathering を土台にして、この関係を逆転させる。

**文字はパーマネントである。** 戦場に出た文字は残り続け、毎ターン攻撃し、
固有能力を発揮する。それ単体で戦力として機能する。

**単語は陣形である。** 並んだ文字が登録ワードと一致すると、**文字を消費せずに**
追加効果が継続的に乗る。文字は引き続き殴り続ける。

この構造にすると、単語は「作って終わり」ではなく「維持するもの」になる。
そして相手には**陣形を崩す**という明確な目的が生まれる。`FIRE` の `I` を除去すれば
陣形は壊れ、効果は消える。MTG の除去と戦闘の駆け引きが、そのままゲームの中心になる。

### 1.3 文字を 2 つの性質に変換する

| 文字の性質 | ゲーム上のステータス |
| --- | --- |
| アルファベット順（A=1 … Z=26） | **順位** — 連番陣形の判定 |
| 言語中での出現頻度・希少性 | **コスト / パワー / タフネス / デッキ投入上限** |
| 母音か子音か | **マナ源かクリーチャーか** |

希少性の数値にはスクラブルの文字スコアを流用する。
英語という言語の実際の構造が、そのままゲームバランスになる。

### 1.4 言語の壁への対処

辞書全体は参照しない。ゲーム内に登録された **コンボワードだけ**が陣形として成立する。

- 全ワードはゲーム内の「ワード図鑑」でいつでも一覧・検索できる
- 中学英単語レベルに限定し、**単語の意味と効果を一致させる**

さらに v0.3 では、**単語を 1 つも知らなくても戦える**。文字は単体で戦力になり、
連番陣形という言語非依存の道も残してあるため、単語は「上級者の伸びしろ」として機能する。

## 2. 基本ルール

### 2.1 勝利条件

- 相手のライフポイント（LP）を **0** にする
- 相手のデッキが尽きた状態で相手がドローする（デッキアウト）

初期 LP は **60**。

### 2.2 対戦形式

**非同期対戦 ＋ AI**。相手プレイヤーの構築したデッキデータを借り、AI が操作する。

### 2.3 試合の長さ

目安 **3〜5 分 / 8〜12 ターン**。片手・縦持ちで操作できること。

## 3. 戦場

```
┌─────────────────────────────────────┐
│  相手 LP 60    シールド 0            │
│  ┌───┬───┬───┬───┬───┐              │
│  │ S │ T │   │ B │   │  相手の戦場     │
│  └─┬─┴─┬─┴───┴─┬─┴───┘              │
│    │   │       │   ← レーンで対峙する  │
│  ┌─┴─┬─┴─┬───┬─┴─┬───┐              │
│  │ F │ I │ R │ E │   │  自分の戦場     │
│  └───┴───┴───┴───┴───┘              │
│   └──── FIRE 陣形 ────┘              │
│  自分 LP 60    エナジー 3            │
└─────────────────────────────────────┘
```

### 3.1 レーン

- 戦場は **5 マス**の横一列。左から右へ 0〜4 の**レーン**と呼ぶ
- 自分のレーン `i` は、相手のレーン `i` と**対峙する**
- 文字は**空いている任意のレーン**に出せる。埋まっているレーンには出せない

順序が意味を持つのは、単語を左から右へ読むためである。
MTG の戦場は順不同だが、本作では並び順が陣形と戦闘の両方を決める。

### 3.2 どのレーンに置くかが戦術になる

- 相手の弱い文字と対峙するレーンに置けば、一方的に討ち取れる
- 相手が空けているレーンに置けば、本体に直接ダメージが通る
- しかし**陣形を組むには並び順を守る必要がある**

「`FIRE` を完成させたいが、その並びだと相手の `Z` と正面衝突する」という
ジレンマが常に発生する。これが本作の中心的な判断になる。

## 4. カード

### 4.1 ステータス

| 項目 | 説明 |
| --- | --- |
| **文字** | A〜Z |
| **順位** | 1〜26。連番陣形の判定に使う |
| **コスト** | 場に出すのに必要なエナジー。母音は 0 |
| **パワー** | 戦闘で与えるダメージ |
| **タフネス** | この値以上のダメージを受けると破壊される |
| **クラス** | `vowel` / `core` / `heavy` / `rare` |
| **デッキ投入上限** | 1〜4 枚 |
| **能力** | 常在・毎ターン・登場時のいずれか |

### 4.2 母音はマナ源である

**A E I O U は MTG の土地に相当する。**

- **1 ターンに 1 枚だけ、エナジーを払わずに出せる**
- 戦場にある母音 1 体につき、毎ターン **エナジー 1** を生む（`E` だけは 2）
- ステータスは **1/2**。弱いが、それなりに場持ちする
- **母音も文字である。** 単語にも連番にも使える

ここに本作最大の葛藤がある。**`E` をマナ源として温存するか、`ACE` の完成に差し出すか。**
母音は資源であり、同時に単語の要でもある。デッキに何枚母音を入れるかという判断は、
MTG の土地枚数調整そのものになる。

### 4.3 数値の導出

- **コスト** = スクラブル文字スコアの圧縮（8点→7、10点→8）。母音は 0
- **パワー / タフネス** = 子音は `コスト / コスト`、母音は `1 / 2`
- **デッキ投入上限** = スクラブルの文字枚数から導出

全 26 種の確定値は [`data/cards.json`](../data/cards.json) を参照。

### 4.4 デッキ構築

- デッキは **ちょうど 30 枚**、同一文字は投入上限まで
- 母音の合計上限は 18 枚。MTG の土地枚数と同じく、**何枚積むかが最初の設計判断**になる
  - 少なすぎるとエナジーが伸びず、重い子音が腐る
  - 多すぎると戦力が足りない

## 5. ターン進行

1. **アンタップ／マナ** — エナジーを「戦場の母音が生む量」まで回復する
2. **ドロー** — 1 枚引く（先攻の 1 手番目だけはドローしない）
3. **メイン** — 文字を出す。母音は 1 ターン 1 枚まで無料、子音はエナジーを支払う
4. **戦闘** — 自分の文字が一斉にレーンを攻撃する（第 6 章）
5. **終了** — ダメージを回復し、手札上限を超えていれば捨てる

配置枚数の制限はない。**エナジーと空きレーンが許す限り何体でも出せる。**
これは MTG に倣った判断で、資源管理そのものを制約として機能させる。

### 5.1 召喚酔い

**出したターン、その文字は攻撃できない。** 能力は使える。

これがテンポの根幹になる。強力な文字を出しても即座には殴れないため、
相手には除去する猶予が 1 ターン与えられる。

---

## 6. 戦闘

自分のターンの戦闘フェイズに、**召喚酔いしていない自分の文字が一斉に攻撃する。**
攻撃するかどうかの選択はない。ブロッカーの割り当てもない。

レーンごとに、次のように解決する。

### 6.1 対峙している場合

相手の同じレーンに文字がいる場合、**互いにパワーぶんのダメージを与え合う。**

```
自分 レーン2: F (4/4)  ←→  相手 レーン2: B (3/3)
→ B は 4 ダメージを受けて破壊される（タフネス 3）
→ F は 3 ダメージを受けるが生存（タフネス 4）
```

守る側の文字は、攻撃していなくても反撃する。MTG のブロックに相当するが、
**誰がブロックするかはレーンで自動的に決まる**ため、宣言のやり取りが要らない。
非同期対戦と相性がよく、スマホでの操作も軽い。

### 6.2 対峙していない場合

相手のレーンが空いていれば、**パワーぶんのダメージが相手 LP に直接入る。**

### 6.3 ダメージとタフネス

- ダメージは蓄積し、**タフネス以上**になった時点で破壊される
- **蓄積したダメージはターン終了時に回復する**（MTG と同じ）

タフネス 4 の文字は、1 ターンに 4 点まとめて受ければ死ぬが、
2 点ずつ 2 ターンかけて受けても死なない。

## 7. 陣形

戦場の並びが特定の条件を満たすと**陣形**が成立し、**成立している間ずっと**効果が続く。

**陣形は文字を消費しない。** 文字は引き続き戦場に残り、攻撃し、能力を使う。
陣形が崩れれば効果は即座に消える。

### 7.1 ワード陣形

隣接して隙間なく並んだ 2 文字以上が、登録済みコンボワードと一致すると成立する。

- 複数成立する場合は**すべて同時に有効**
- 効果は継続的なもの（全体強化、毎ターンのダメージや回復など）

全リストは [`data/words.json`](../data/words.json) を参照。

| 文字数 | 位置づけ | 効果の規模 |
| --- | --- | --- |
| 2 | 小回り。序盤から組める | 小さな常在強化 |
| 3 | 主力。試合の基本形 | 明確な常在効果、毎ターンの小ダメージ |
| 4 | 大技。維持できれば有利が固まる | 全体強化、毎ターンの大きな効果 |
| 5 | 切り札。戦場を占有する | 勝負を決める継続効果 |

### 7.2 連番陣形

隣接して並んだ順位が**昇順**に連なると成立する。

| 条件 | 内容 |
| --- | --- |
| 隣が昇順（差 1 以上） | 陣形として継続 |
| 隣がちょうど +1（連番） | **ラン**として扱い、効果が強化される |
| `Z` の次に `A` | 環状として繋がる |

長さ n の連番陣形は、**その陣形に属する文字すべてのパワーを +n-1** する
（ランならさらに +1）。単語を知らなくても戦える道として機能する。

### 7.3 陣形を壊す

相手の陣形を崩すことは、除去と同じくらい重要な行動になる。

- 陣形の中の 1 文字を破壊すれば、陣形は崩れる
- `W` のように**並びをずらす**効果は、文字を破壊せずに陣形だけを壊せる

## 8. バランス実測

`tool/simulate.dart` で AI 同士の対戦を数百回まわして数値を確かめる。

    dart run tool/simulate.dart 400

### 8.1 v0.3 の実測結果

| 指標 | v0.2 | v0.3 | 目標 |
| --- | --- | --- | --- |
| 試合の長さ | 8.2 ターン | 7.4 ターン | 8〜12 ターン |
| 先攻勝率 | 51% | 54% | 50% |
| デッキ切れ決着 | 0% | 0% | ほぼ 0% |
| ワード陣形の成立率 | — | 27.6% | 過半 |

先攻勝率は、初期手札を両者 5 枚に揃えたうえで「先攻の 1 手番目はドローしない」
という MTG の是正を入れて 61.5% から 54% に下げた。

### 8.2 未解決の課題

**長いワードがほとんど成立しない。** 試合中に成立した最長のワードは、
2 文字が 52.5%、3 文字が 36.0% で、**4 文字はわずか 1.8%、5 文字は 0%**。
`FIRE` や `LOCK` はデッキに入っているのに一度も成立していない。

原因は 2 つ考えられる。ひとつは試合が 7.4 ターンと短く、4 文字を並べる前に
決着すること。もうひとつは、レーンが戦闘で削り合われるため、特定の並びを
維持し続けること自体が難しいこと。後者は設計意図どおりの難しさでもあるが、
現状では「狙う価値がない」水準まで落ちている。

次に試す手は、試合をもう少し長くすること（LP をさらに上げる）と、
長いワードの効果を今より明確に強くして、リスクに見合う報酬にすること。

**ワード陣形が成立していない手番が 7 割ある。** 2 文字ワードが主戦力に
なっており、単語らしい手応えはまだ薄い。

**能力・陣形による直接ダメージは全体の 1% 未満。** ただしこれは指標の
見かけの問題でもある。`ACE` や `WAR` のようなパワー加算の陣形は、
効果が戦闘ダメージとして計上されるため、この数字には現れない。
陣形が戦闘を通してどれだけ寄与しているかは、別途測る必要がある。

# proto10 合格基準とレビュー記録

1ステージ（3連戦：普通の敵2体 → ボス）を、内容を増やさずに仕上げる。工程ごとに別のレビュワーが基準に照らして判定し、合格するまで直す。

## 合格基準

### A. バランス（`sh tools/run.sh 80 strong <出力先>` と `sh tools/rewards.sh 160 <出力先>` で測る）

| 番号 | 基準 |
| --- | --- |
| A1 | 賢いCPU（strong）のクリア率が 70〜85%（1ターン先まで正確に読むCPU。人が慣れたときの上限に近い） |
| A2 | 単純なCPU（greedy）は strong より15ポイント以上低い。でたらめ操作（random）は5%以下 |
| A3 | ヒーロー別クリア率の最大と最小の差が15ポイント以内 |
| A4 | 全10組（良いほうの並び）のクリア率が 55〜98%（100%に張り付く組がないこと） |
| A5 | 各戦闘の平均ターンが 5〜8、95%点が12以下 |
| A6 | 勝率が 第1戦 ≧ 第2戦 ≧ ボス。ボスの勝率は 70〜88% |
| A7 | 報酬：どの新カードも、いちばん良い入れ替え先でクリア率がプラス。どの報酬も単独で+35ポイントを超えない |
| A8 | 初期カード20枚すべてが、1冒険あたり1.5回以上使われる。固有スキルも全員1.5回以上 |
| A9 | 抜け道がない（何もしない・後ろに下がり続けるなど、考えずに勝てる手順がない） |

### B. ルールの分かりやすさ

| 番号 | 基準 |
| --- | --- |
| B1 | 画面の「ルール」とカードの文面だけで、エンジンの挙動をすべて説明できる（書かれていない挙動がない） |
| B2 | カード・スキルの文面とエンジンの処理が一致している |
| B3 | 用語が統一されている（同じものを別の名前で呼ばない） |
| B4 | 例外処理（前衛が空、倒れている味方、盾と反撃、かばうと全体攻撃など）の結果が、画面の「なぜ」で説明される |

### C. 画面（スマホ縦 375×650 と 390×844）

| 番号 | 基準 |
| --- | --- |
| C1 | どの画面でも、はみ出し・重なり・切れた文字がない |
| C2 | 自分のターンに「敵が次に誰へ何ダメージ与えるか」「自分がそれでどうなるか」が一目で分かる |
| C3 | 1つの行動が2タップ以内（対象選びがあるときは3タップ以内）で終わる |
| C4 | 押せるものは高さ40px以上。押せないものは見た目で分かる |
| C5 | 何が起きたか（ダメージ・盾・反撃・怒り・ボスの本気）が再生で追える |
| C6 | 初めての人が、タイトルから1戦目の最初の行動までに迷わない |

### D. コード

| 番号 | 基準 |
| --- | --- |
| D1 | エンジンの不変条件のテストが通る（`node tools/test.js`） |
| D2 | ブラウザでの通しプレイ（3連戦・報酬・入れ替え・敗北）でエラーが出ない |
| D3 | 使われていないコード・文言が残っていない |
